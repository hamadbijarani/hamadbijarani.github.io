Estimation assumptions & limitations

Representative dense, non-GQA transformer: 32 layers, hidden width 4096, feed-forward width 14336. Not a named checkpoint. Q/V: 4Ldr; attention: 8Ldr; all linear: Lr[8d + 3(d + f)]. Embeddings and output head are excluded.

LoRA adapters remain mixed precision. Memory uses frozen weights × 1.2 for overhead, 16 bytes per trainable parameter for Adam-style training, and a fixed 2 GiB activation allowance. Full fine-tuning uses 16 bytes per backbone parameter + 2 GiB. 1 GiB = 2³⁰ bytes.

These are planning estimates, not measured performance. Sequence length, batch size, checkpointing, grouped-query attention, kernels, and quantization metadata change actual requirements. Parameter reduction is not VRAM reduction; 99.8% is not guaranteed.

Machine Learning / NLP Systems · Peer-Reviewed Journal Publication

Energy-Efficient NLP Through Tiny-Model Distillation, Pruning, and Quantized Inference

Hamadullah Bijarani · Kashf Journal of Multidisciplinary Research (KJMR), 2026

Model Compression / Quantization

Journal link

Abstract

Transformer models achieve state-of-the-art NLP performance but face deployment constraints due to high inference energy costs. Numerous techniques have been proposed to optimize model operations. Due to limitations of hardware and time, we analyzed a few of them, which are knowledge distillation, unstructured pruning, and quantization within a unified pipeline for BERT and TinyBERT. Results demonstrate that the Distilled Student serves as the dominant baseline, offering the lowest energy per sample among all variants. Conversely, while post-training quantization and pruning reduce model size, they introduce significant kernel overheads on GPUs. Notably, combining INT8 quantization with aggressive pruning results in severe latency penalties, causing up to a 4× increase in energy consumption compared to the standard Student. These findings underscore the critical disparity between theoretical compression metrics and hardware-realized energy efficiency.
